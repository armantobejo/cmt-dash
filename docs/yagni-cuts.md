## Cuts (ranked, biggest first)

1. `yagni` Drop `run_sync(..., python_exe)` parameter flexibility + `_PYTHON_EXE` env in `src/app/sync.py`: only caller `main.py` passes `sys._base_executable`. Single caller = speculation. Replacement: hardcode `sys._base_executable` inside `sync.py`. → `-2 params, -3 lines`

2. `delete` Remove one-off dev scripts from repo active tree: `analyze_dbf.py`, `dump_fields.py` (peak at git history; they were scaffolding for the schema exploration). `na_cargo_column_analysis.json` is a generated analysis dump — remove or move to `docs/analysis/` if referenced by anything. → `-2 files, -1 json dump`

3. `native` Cookie flags: `set_cookie(..., samesite="lax")` is repeated in `main.py` twice. Starlette `Response.set_cookie` accepts the same kwargs — no wrapper needed. Consolidate flags into ONE helper `_session_cookie(resp, token)` in `auth.py` where the cookie NAME already lives (single source of truth). → `-4 lines, -1 repetition`

4. `stdlib` `tools/extract_schema.py` uses `dbf` library + hand-rolled `parse_field` regex when `dbfread` (already a dependency in `requirements.txt`!) can read headers: `DBF(path).fields` gives `(name, type, length, decimal_count)` without the regex. Replacement: rewrite `extract_schema.py` on `dbfread`, kills `parse_field` + `TYPE_MAP`. → `-20 lines, -1 dep (dbf)`

5. `yagni` `db.py::table_count(table)` accepts any table name string → SQL interpolation risk (flagged in plan T015). Two callers, both constants. Replacement: whitelist `table_count()` to a frozen set; no dynamic tables exist in this app. → kills an injection foot-gun, `-5 lines`

6. `delete` `cookies.txt` (135 B) in repo root — likely leftover session cookie dump from manual curl testing; DANGER: may contain a live session token. Delete from tree + ensure `.gitignore` covers it. Verify contents first (see below, redacted if sensitive). → `-1 file, 0 lines`

7. `shrink` `src/app/__init__.py` is empty (0 bytes). Keep — it makes `src/app` a package; no cut.

8. `yagni` Spec: `docs/design_system.md` documents a "sync status indicator" idea — CUT from US3 scope unless the owner explicitly wants it. The UI already shows `sync_time` in templates; adding an API + poller is speculative. → plan.md T033 scoped back to "stale flag" only.

9. `yagni` `layout.js` "Add SSE when sync exceeds 10s" comment = speculative push-tech. The fetch-block pattern is fine for this scale. Recorded as consciously deferred; NOT in scope.
